npm # Northstar E-Commerce — Six-Person GitHub Collaboration Guide

## One repository, six branches

**Do not create six separate repositories.** The project owner publishes the **complete project** once to one repository. Everyone clones it, creates a separate feature branch, edits their assigned files, and submits pull requests (PRs) for review. Individual member ZIPs are reference/ownership packages, **not standalone applications** and are **not meant to be uploaded as separate repositories**.

## Assignment table

| Member | Branch | Responsibility |
|---|---|---|
| 1 | `feature/landing-page` | Landing page, navigation and shared styling |
| 2 | `feature/store-catalog` | Product catalog and store browsing |
| 3 | `feature/cart-checkout` | Cart and customer checkout UI |
| 4 | `feature/customer-account` | Customer profile, address and order history |
| 5 | `feature/admin-dashboard` | Admin inventory, metrics and orders UI |
| 6 | `feature/backend-database` | Express APIs, database, authentication and backend tests |

### File ownership
**Member 1 — Landing page, navigation and shared styling**: `frontend/src/App.jsx`, `frontend/src/styles.css`, `frontend/src/main.jsx`, `frontend/index.html`
**Member 2 — Product catalog and store browsing**: `frontend/src/StorePage.jsx`
**Member 3 — Cart and customer checkout UI**: `frontend/src/CartPanel.jsx`, `frontend/src/CartDrawer.jsx`
**Member 4 — Customer profile, address and order history**: `frontend/src/CustomerDashboard.jsx`
**Member 5 — Admin inventory, metrics and orders UI**: `frontend/src/AdminDashboard.jsx`, `frontend/src/OrdersPanel.jsx`
**Member 6 — Express APIs, database, authentication and backend tests**: `backend/src/adminRoutes.js`, `backend/src/customerRoutes.js`, `backend/src/orderRoutes.js`, `backend/src/server.js`, `backend/src/seed.js`, `backend/src/db.js`, `backend/src/orderRules.js`, `backend/test/orderRules.test.js`, `backend/package.json`, `backend/.env.example`, `database/schema.sql`, `database/step3-migration.sql`, `database/step4-migration.sql`, `frontend/src/api.js`

Member 1 owns the shared `frontend/src/styles.css` and app-level routing in `App.jsx`. All other members should ask Member 1 for shared CSS or routing changes instead of editing that file directly. Member 6 owns `frontend/src/api.js` and the API contracts; coordinate API changes with Member 6. Member 4 owns the customer orders UI in `CustomerDashboard.jsx`; Member 5 owns admin orders UI in `OrdersPanel.jsx`.

## Owner: initial GitHub upload

1. Extract the **complete six-person repository ZIP**, or use the current verified working project. Confirm the folder contains `frontend/`, `backend/`, `database/`.
2. Make a backup. Verify `.env` and any customer data dump are **not included**. Never commit secrets or `node_modules`.
3. Create a new empty repo at https://github.com/new named `northstar-ecommerce` (skip GitHub's autogenerated README/license/.gitignore for this initial push).
4. From the project root, run:

```bash
git init
git branch -M main
git add .
git status
git commit -m "Initial working Northstar ecommerce system"
git remote add origin https://github.com/YOUR_USERNAME/northstar-ecommerce.git
git push -u origin main
```

If Git was already configured, inspect `git status` and `git remote -v` first and adapt the commands, rather than recreating the repository or overwriting history.

5. Invite **five teammates**: GitHub repository **Settings > Collaborators** (or Collaborators and teams) > **Add people**. Each accepts the invitation.
6. Configure `main` protection through **Settings > Rules > Rulesets** or **Branches**, requiring PR review when available on your GitHub plan/repository visibility.

## Each teammate: clone, branch, commit, PR

```bash
git clone https://github.com/YOUR_USERNAME/northstar-ecommerce.git
cd northstar-ecommerce
git switch -c feature/YOUR-ASSIGNED-BRANCH
# edit only assigned files
git status
git add path/to/assigned-file
git commit -m "Improve my assigned module"
git push -u origin feature/YOUR-ASSIGNED-BRANCH
```

Replace `feature/YOUR-ASSIGNED-BRANCH` with your **exact** branch from the assignment table. On GitHub, click **Compare & pull request**; select `main` as the target; describe changes, add screenshots when relevant, and request a teammate review. Merge only after tests and review pass.

To begin new work after a PR merges:

```bash
git switch main
git pull origin main
git switch -c feature/next-improvement
```

Never push directly to `main` during normal collaboration. Do not force-push shared branches. If a conflict affects another person's module, coordinate with that owner before resolving.

## Verify before merging

- Frontend: `cd frontend && npm install && npm run build`
- Backend: `cd backend && npm install && npm run check && npm test`
- Integration: Run MySQL in XAMPP, start backend and frontend, and check login, product browsing, cart, delivery address, COD checkout, inventory changes, order statuses and admin tools.
- Each developer creates their **own** local `.env` from `.env.example` and uses a personal test database. No passwords, production secrets or customer database dumps in Git.

## Important

Uploading to GitHub publishes source code, **not** a hosted website or a running XAMPP server. Never deploy the starter admin password `admin123` to an internet-accessible system. The member ZIPs reflect the existing source code with no application behavior changes; this reorganizes ownership, not features.
